### AZ-104:AzureでのIDとガバナンスの管理
##### Microsoft Entra IDの概要
Microsoft Entra ID は、Microsoft が提供するクラウドベースの ID およびアクセス管理サービス
このモジュールは、以下の内容について包括的に理解していただくことを目的としています。

Microsoft Entra ID について説明する。
Microsoft Entra ID と Active Directory Domain Services (AD DS) を比較する。
クラウド アプリ用のディレクトリとして Microsoft Entra ID を使用する方法について説明します。
Microsoft Entra ID P1 と P2 について説明する。
Microsoft Entra Domain Services について説明する。

安全なリソースアクセス
* 認証：Auth N (ADDS,EntraID)
* 承認(認可)：Auth Z (ACL，ユーザ権利,RBAC)リソースで承認

Entra ID であれば業界標準のプロトコル(https 等)で認証できる。エンドポイントのOSに依存しない。
オンプレの認証(ADDS)等(Corp.comドメイン)はKerberosで認証したり…。


認証：Entra ID
承認(認可)：リソースごとのACL,RBAC(Office 365,Exchange Online,VM，Vnet)，OAuth
プロビジョニングを行うことでSSOで他サードパーティー(DropBox等)を利用できる。
Entra ID ではSAML、WS-Federation、OpenID Connect などの HTTP および HTTPS プロトコルを認証に使い、OAuth を認可に使う

オンプレの認証サーバとクラウドのEntra IDが共存している場合は，Entra Connectなどを使って同期(Sync)している場合もある。

Entra ID はマルチテナントとして設計されている。個々のディレクトリインスタンスが確実に分離されるように実装されている。
テナント：個々のEntra インスタンス
複数の Microsoft Entra テナントを用意しておくと、他のテナントに影響を与えることなく 1 つのテナント内で Microsoft Entra 機能をテストしたいときに便利な場合がある

Entra ID P1 P2 Premiumプラン
P1 は E3に包含，P2 は E5に包含されているので個別契約している意識はない企業が多い
Premium バージョンでは、ユーザー プロビジョニングごとに追加のコストが必要

P2 ライセンス
* Entra Identity Protection ユーザー アカウントを監視および保護するための拡張機能が提供されます。 ユーザー リスク ポリシーとサインイン ポリシーを定義できます。 さらに、ユーザーの動作を確認し、ユーザーにリスクのフラグを設定することもできます
* PIM(Privileged Identity Management) 、管理者などの特権ユーザーに対して追加のセキュリティ レベルを構成できます。 Privileged Identity Management を使用して、永続的および一時管理者を定義します。 また、タスクを行うために管理者特権を使用したいユーザーがいる場合に常にアクティブ化するポリシー ワークフローを定義する。

##### IDを作成，構成，および管理する
アイデンティティは3つ定義される
* クラウドID
* ディレクトリ同期ID
* ゲストID
ディレクトリ同期IDはADDS等から同期されるユーザなのでUI上登録できるのはクラウドIDとゲストIDのみ

削除されたユーザアカウントは，30日後に自動的にMicrosoft Entra IDから完全に削除されます。

Entra IDでは2つの種類のグループを定義できる
* セキュリティグループ - グループの最も一般的な種類であり、ユーザーのグループの共有リソースへのメンバーとコンピューターのアクセスを管理するために使用されます。 たとえば、特定のセキュリティ ポリシーのセキュリティ グループを作成できます。 このようにすることで、各メンバーに個別にアクセス許可を追加する必要なく、すべてのメンバーに一連のアクセス許可を一度に付与できます。管理者が使用できる。
* Microsoft365グループ - メンバーに共有メールボックス、予定表、ファイル、SharePoint サイトなどのアクセス権を付与することで、コラボレーションの機会を提供します。 このオプションでは、組織外のユーザーにグループへのアクセス権を付与することもできます。 このオプションは、ユーザーおよび管理者が使用できます。

メンバーシップのルールとして動的と静的を選択できる

Azure サブスクリプション
サブスクリプションは管理、課金、スケールの単位です。 リソース グループがリソースを論理的に整理する方法と同様に、サブスクリプションを使用すると、リソース グループを論理的に整理し、課金を容易にできます。
Azure の使用には、Azure のサブスクリプションが必要です。 サブスクリプションにより、Azure の製品とサービスへのアクセスが認証および承認される。


Azure管理グループ
リソースはリソースグループにまとめられ、リソースグループはサブスクリプションにまとめられる。
管理グループはサブスクリプションより上のレベルのスコープを提供されている。
なぜ管理グループが必要なのか。 → 多数のサブスクリプションがある場合は、それらのサブスクリプションのアクセス、ポリシー、コンプライアンスを効率的に管理する方法が必要になることがあるため。
管理グループ内のすべてのサブスクリプションは、リソース グループがサブスクリプションから設定を継承し、リソースがリソース グループから継承するのと同じ方法で、管理グループに適用された条件を自動的に継承する。管理グループを使うと、サブスクリプションの種類に関係なく、大きな規模でエンタープライズレベルの管理を行うことができる。
